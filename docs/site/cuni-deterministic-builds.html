Deterministic builds: "it built on my machine" is not a proof

"It built on my machine" is the industry's most expensive sentence. Security, science, and compliance all need the same guarantee: same inputs → same outputs, everywhere, every time.

The failure mode

A release artifact built on two CI runners differs by a timestamp embedded in the binary. The checksums don't match, the audit can't confirm what shipped, and the incident response starts from "which one is real?"

What CuNi proves today: partial

The receipt model already does half the job honestly: every cuni check --receipt records source_hash (SHA-256 of the .cuni bytes), cuni_version (pinned — a pass from one version is never read as a pass from another), and stdout_hash (SHA-256 of the gold stdout), optionally signed with Ed25519. That is reproducible verification: anyone can re-run the proof and compare hashes. Agent-Rider consumes these receipts to refuse stale or mismatched claims.

What it does not claim

Bit-identical build artifacts across machines and toolchains is not claimed. CuNi proves program behavior is identical; it does not currently prove that two separate compilations emit byte-identical binaries.

What is next

Extend the receipt model from behavior to artifacts: hash the emitted target sources per seat, pin toolchain versions in the receipt, and make cuni verify-receipt re-derivable by a stranger. The falsifiable milestone: two clean-room installs on different machines produce receipts with identical source_hash and stdout_hash for the full law suite.
