Agent policy gate: prove the policy before the agent runs it

Identity says who an agent is. CuNi guarantees the policy that identity carries behaves the same everywhere it executes. Agents that write and run code across systems cannot tolerate "close enough."

How it works

An agent's policy is written as a CuNi law and proven byte-identical across the seats it will execute on. Studio's POST /api/pass is live on the py / go / js gate — PASS or refuse, no soft pass. A policy that would behave differently on one seat than another never gets the receipt, and a receipt that is stale or mismatched is refused.

Honesty: Rider's require-PASS gate (CUNI_STUDIO_PASS_REQUIRED) is off today — seats still run without a citizen PASS. We are not claiming a live enforced gate on Rider. Check exactness on CuNi when you want the proof; execute on Rider seats either way. Start at /rider.

Why it matters with Warrant

Warrant writes what an agent may do — hosts, actions, spend, calls — and the spend gate itself is a CuNi law (spend-control.cuni, amount <= cap). The policy gate and the spend gate are the same idea at two layers: prove the rule behaves identically everywhere, then enforce it. See Warrant and Money: settlement and Warrant budget trees.
