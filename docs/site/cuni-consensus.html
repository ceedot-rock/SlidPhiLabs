Consensus: the same escrow law on every chain, or refuse

Consensus is agreement. Every validator must compute the identical state transition from identical inputs, or the chain forks. Cross-chain work multiplies the problem — the same escrow logic, in different languages, on different VMs.

The failure mode

An escrow contract ported from Solidity to Rust for a second chain handles a boundary amount differently — one truncates, one rounds. Funds lock on one chain and release on the other. The bug is invisible to every test suite that only runs one chain's toolchain.

What CuNi proves today: proven (logic cores)

One escrow / transfer-validation law proven byte-identical on EVM (Solidity, compiled by real solc into a deployable contract), Rust, and Go. Six chain emitters — ink!, Move, Vyper, Cairo, Clarity, Cadence — each emit the proven logic core plus the chain shell in the chain's idiom, in delimited regions. The fee-schedule law runs byte-identical on all six.

What it does not claim

Logic cores are proven; chain shells are shape-asserted and snapshot-pinned, not compiled, where no chain toolchain exists on the check machine (Solana shell included). Nothing here is deployed to a live chain by the proof itself. Cross-chain state agreement — proving two deployed contracts converge, not just two logic cores — is not claimed.

What is next

Close the shell gap per chain as toolchains become available on the check machines, each closed shell a publishable milestone. Then: state-convergence proofs, where the deliverable is not "both cores agree" but "both deployed contracts, given the same transaction log, reach the same state."
