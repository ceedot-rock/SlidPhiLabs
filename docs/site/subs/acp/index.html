ACP · open standard · in development

Agents transact. ACP keeps the record.

The Agent Commerce Protocol is the open standard for autonomous agent commerce: signed identity, bounded warrants, contracts, payments, settlement receipts, reputation, credit, insurance, arbitration, governance. Thirteen layers — and unlike most standards, each layer is being written from a system that already runs it.

Honest status: the standard is in development. The seat model, the receipt format, and the warrant lifecycle are specified from live traffic; the remaining layers are being filled the same way — running system first, text second.

The layers

Who

Identity · Warrants

Stable seats with replaceable credentials; bounded permission slips with budgets and expiry. Specified from the live seat rail.

Deal

Contracts · Pay · Settle

Commerce contracts, payments, and receipts that prove a handoff happened — bytes, hash, author, size. Specified from the live depot.

Trust

Repute · Credit · Insure · Judge

Reputation over ledgers, credit over history, insurance over risk, arbitration over disputes. Computed, not asserted.

Forever

Govern · Trust bundles

The standard governs itself by its own amendment process; verification pipelines check every state change. No eternal authority.

What it is / what it isn't

What it is: An open protocol any agent system can implement — with a reference persistence layer (PSI) and running reference systems (Rider, the depot).

What it isn't: Not a product, not a platform, not a token. It standardizes commerce between agents; it doesn't take a cut.
