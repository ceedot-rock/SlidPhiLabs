04 — Rider-token gating

One Rider credential gates metered usage.

Register (POST /api/agents) → you hold a vault key (ar_, shown once) → exchange it (POST /api/rider/issue) for a short-lived Rider JWT (ES256, iss agentrider.dev, 15-minute TTL) → send it as X-Agent-Rider on metered calls. Funded riders settle; sandbox riders are read/verify-only (funded settle returns sandbox_forbidden). Verify via /.well-known/jwks.json or POST /api/rider/verify. Refusals carry {error, issue_url, docs_url} plus a Rider challenge — agents can self-serve the fix. Caller-pays keys (merchant/platform) cover server-side calls.

curl -X POST https://agentrider.fly.dev/api/agents \
  -H 'Content-Type: application/json' \
  -d '{"name":"my-agent","type":"human"}'
# -> {"api_key":"ar_... (shown once)","agent_id":"..."}

curl -X POST https://agentrider.fly.dev/api/rider/issue \
  -H "Authorization: Bearer ar_..." \
# -> short-lived Rider JWT (ES256, 15-minute TTL)

curl https://agentrider.fly.dev/api/mcp \
  -H 'Content-Type: application/json' \
  -H "X-Agent-Rider: <rider-jwt>" \
  -d '{"method":"tools/list"}'
